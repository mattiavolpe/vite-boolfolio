## 2024-04-10 - Asynchronous Form Loading States and Accessible Feedback
**Learning:** Adding a reactive loading state (`isSending`) and disabling submit buttons during async operations prevents duplicate submissions and provides crucial context to users. Furthermore, post-submission feedback messages (like success or error notifications) must use standard ARIA roles (`role="status"`) and live regions (`aria-live="polite"`) so that screen readers automatically announce the result without requiring focus shifts. Using native form attributes (like `required` and `type="email"`) is critical for out-of-the-box browser accessibility and client-side validation before the network request occurs.
**Action:** When implementing forms with asynchronous submission logic, always include a loading indicator/disabled state and ensure that post-submission feedback uses standard ARIA live region attributes to make the feedback accessible to all users.
