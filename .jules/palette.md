## 2024-03-24 - Async Form Feedback and Native Validation
**Learning:** Found an async form lacking proper validation types (`type="mail"` instead of `type="email"` or `type="text"`) which breaks native mobile keyboard support and browser validation. Additionally, the async submission using `axios` provided no loading state or user feedback (success/error), leaving the user confused whether their action succeeded or if the form froze.
**Action:** Always verify input `type` attributes for correctness (`email`, `text`, etc.). When handling asynchronous form submissions, explicitly bind a boolean `isSending` state to disable the submit button and inputs to prevent double submissions. Also, ensure explicit success/error toast notifications or inline alerts are displayed upon completion so the user receives clear feedback.
