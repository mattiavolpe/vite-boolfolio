## 2024-04-04 - Accessible Form Feedback State
**Learning:** For async form submissions without page reloads, a robust UX requires four elements: disabling the submit button, visually communicating the "sending" state, gracefully handling network errors (even in dev environments), and using `role="status"` with `aria-live="polite"` so screen readers announce the success or error feedback without stealing focus. Form validation using standard HTML5 attributes (`type="email"`, `required`) is also critical for catching errors before the API call.
**Action:** When implementing form submissions, always establish an `isSending` state to manage the button's interactivity, pair it with post-submission feedback that is both visually clear and accessible via ARIA live regions, and ensure appropriate `type` and `required` attributes are set.
